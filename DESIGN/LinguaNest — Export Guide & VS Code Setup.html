Developer Guide

Export screens to your local VS Code project

Every LinguaNest screen is shipped as a self-contained HTML file with scoped CSS. You can copy them directly into your project, or wire them up to a framework of choice. Below is the fastest path from design to working code on your machine.

1
Create a project folder

Open VS Code, then open your terminal and scaffold a clean working directory.

$ mkdir linguanest-app $ cd linguanest-app $ mkdir screens assets shared
i
Pro tip: If you plan to build a multi-page site, keep the raw screens in a /screens folder. You can route to them from an index.html later.
2
Copy screen HTML files

Each screen in the project panel is a complete HTML document. Click into a screen, select all markup, and paste it into a new file.

<!-- screens/dashboard.html --> <!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>Dashboard</title> <style> /* All CSS lives here — no external dependencies */ </style> </head> <body> <!-- Page content --> </body> </html>

Repeat for every screen you want to ship. Rename files to match your routing preference.

linguanest-app/ ├── screens/ │ ├── index.html │ ├── login.html │ ├── dashboard.html │ ├── explore.html │ ├── lesson-player.html │ └── profile.html └── assets/ └── images/
3
Link screens together

Navigation in each screen uses standard anchor tags. Update href paths to point at the correct files in your folder structure.

<!-- Before: raw hrefs --> <a href="#">Dashboard</a> <!-- After: real file paths --> <a href="./dashboard.html">Dashboard</a> <a href="./explore.html">Courses</a>
4
Serve with Live Server

Install the Live Server extension from the VS Code marketplace, then right-click index.html and choose "Open with Live Server."

$ npx serve screens # or just use Live Server in VS Code
  • Instant hot-reload as you edit CSS
  • Clean localhost URL for mobile testing
  • No build step required for static shipping
5
Convert to a framework (optional)

If you need routing, state, or a component library, migrate the markup and CSS tokens into your framework of choice.

/* shared/tokens.css */ :root { --bg-page: #F8F5F2; --accent: #C25E38; --font-display: "Bricolage Grotesque", sans-serif; }

Copy the design tokens first. Then build components from the repeating UI patterns (cards, buttons, nav items) and import them into your routed pages.

i
Images: The system uses imageRef IDs instead of URLs. Replace each <img src="..."> with real assets in your /assets/images folder.

Root cause analysis: the source `backend/src/contentLibrary.js` and `backend/src/seed.js` were valid and locally passed validation, but the live production backend was not guaranteed to be using the same Mongo database or the same content sync path. In practice the deployment was pointing to a stale or different database, and the app relied on a manual/partial seed path rather than an explicit content synchronization flow. Local tests only proved the content library in source code was correct; they did not prove the remote database had been updated or that the deployed backend was running the intended revision. The fix is to enforce explicit content deployment commands, stable course IDs, validation-first seeding, and a production-safe sync process that targets a verified DB before any remote mutation. |
